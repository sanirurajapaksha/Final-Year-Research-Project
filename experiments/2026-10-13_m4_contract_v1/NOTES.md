# M4 contract v1: byte-only evaluation

Task: W2-08. Owner: Nethmi Herath. W2-08 remains incomplete.

## Scope and measurements

This is a byte-only evaluation on one hand-written synthetic CART_ADDR sample:
`data/fixtures/m1/scenario_01/telemetry.json`. Its source and `ground_truth.json`
declare synthetic provenance. All 27 records are included: 8 metrics, 9 logs,
6 spans and 4 Kubernetes records. No filtering, model calls or cluster commands occur.

The main comparison is **15.59% versus compact JSON**: 4,438 B to 3,746 B TSV.
The secondary comparison is **21.93% versus default JSON**: 4,798 B to 3,746 B.
The runner calculates both percentages as `100 * (json_bytes - tsv_bytes) / json_bytes`.
Compact JSON uses `json.dumps(batch.records, ensure_ascii=False, separators=(",", ":"))`;
default JSON uses `json.dumps(batch.records, ensure_ascii=False)`.
Both are exact UTF-8 bytes without an added newline, excluding batch metadata.
The TSV includes its shared header, JSON cells, quoting, tabs and CRLF rows.
The compressor's `original_size` keeps its existing default JSON semantics;
the runner checks that field against default JSON and compares compact JSON separately.
No token savings, RCA accuracy or general benchmark performance is established.

## Reproduction and evidence

From a clean checkout containing the optional branch/upstream runner fix,
install the existing project dependencies and run from the repository root:

```powershell
.venv\Scripts\python.exe experiments/2026-10-13_m4_contract_v1/run.py --output-dir experiments/2026-10-13_m4_contract_v1_reproduction
```

On Linux/macOS use `.venv/bin/python`. Use a fresh output directory: the runner
refuses existing config/results and rejects tracked or untracked Git changes
before reading fixtures, measuring or creating output. Ignored environment/cache
files do not affect Git cleanliness. Commit the runner before measuring.
`config.json` records the full clean source SHA, optional branch/upstream, fixture hashes,
Python/platform/Pydantic environment, UTC time and exact serialization settings.
`results/compact.json`, `default.json` and `telemetry.tsv` retain exact payload
bytes; `summary.json` records their hashes and calculated measurements.
Fixture copies, dirty-source patches/hashes, check indexes and lint logs are unnecessary.
Raw results are generated by the runner and never edited by hand.

The saved evidence remains the original run at `789f7f1398854a4cc827175f62854b7f0510d336`.
That commit's runner fails on detached HEAD or a branch without an upstream;
use the later runner fix for those checkouts. The fix changes only Git metadata
collection, leaving `src`, fixtures, measurement logic and saved evidence intact.
New runs record their actual source commit; they do not relabel the original run.
Detached HEAD records `branch: null`; missing upstream records `upstream: null`.
Git status and source commit queries remain mandatory and fail on Git errors.

The original input/provenance hashes identify the Windows CRLF checkout bytes.
Git stores LF blobs: the fixture blob SHA-256 is
`72beae15faa4debe6de965b106d298c62b3300e3a9d550482919a9a87d6a15c7`;
the ground-truth blob SHA-256 is
`f255d19cd4e4b01c688fbfdb6683edca5e4f38e28c3d940692abae1aa667e6d2`.
Checkout newline conversion can therefore change these raw file hashes.
The parsed JSON is identical, and all three serialized payloads are byte-identical
to their committed Git blobs. Serialized UTF-8 payloads are the size baselines.

The runner checks M1 contract validation, round-trip exact values/types/field names,
record order, duplicate multiplicities, shared header/row counts, input immutability
and unchanged `alert_time`. This sample has no exact duplicates; M4 unit tests
separately exercise duplicates and optional/default cases.
